= Changelog
:description: Release history for Maildeno and its SDKs.

All notable changes to Maildeno are documented here. Maildeno follows https://semver.org[Semantic Versioning]. The Editor, JavaScript/TypeScript, Python, and PHP SDKs are versioned independently — the Editor is currently at **v{editor-version}**, the local JS Renderer at **v{renderer-version}**, the JS SDK is currently at **{js-sdk-version}**, the Python SDK at **{py-sdk-version}**, and the PHP SDK at **{php-sdk-version}**.

Entries are grouped by release date. Where multiple SDKs shipped the same change on the same day, they're listed together under one heading instead of being repeated per SDK; where SDKs shipped different changes on the same day, each gets its own subsection.

== 2026-11-11

**Maildeno Editor**

=== Long words no longer overflow the email body

**@maildeno/editor v0.4.16**

==== Fixed

**Long words no longer overflow the email body.** A long unbroken token — a URL, a tracking ID, a hash — ran past the edge of the body in all three exports and made the message scroll sideways on narrow screens. The body now breaks long words in HTML, MJML and React Email alike.

Each output needed its own fix. In HTML the rule goes on the body element. In MJML it goes in an `<mj-style>` block, because `mj-body` drops an inline `style` attribute. In React Email it goes on the container's style object as `wordBreak: "break-all"`.

`word-break: break-all` breaks wherever a line runs out of room, so a long word is split mid-word rather than pushed past the edge. The catch is that it applies to every word, not only the ones that would overflow: a normal word at the end of a full line may now be split too. Outlook desktop ignores the property, so there a long token can still overflow — nothing changes for that client.

++++
<br/>
++++

**Removed unused padding from the Divider container in the editor.** The container already has its margin explicitly controlled, so applying component padding introduced unnecessary spacing around the divider when selected.

++++
<br/>
++++

**Opensource Renderer v0.3.2** · **JavaScript/TypeScript v2.2.1** · **Python v2.1.2** · **PHP v1.1.1**

=== Rendering engine updated (Opensource Renderer, JavaScript/TypeScript, Python, PHP)

==== Fixed

**Long words no longer overflow the email body.** A long unbroken token — a URL, a tracking ID, a hash — could extend beyond the email body's boundaries and cause horizontal scrolling on narrow screens. The HTML, MJML and React Email renderers now apply `word-break: break-all` to the body container, ensuring long tokens wrap instead of overflowing.

The rule splits words wherever necessary to fit the available width, including normal words at the end of a full line. Outlook desktop does not support this property, so long tokens may still overflow in that client.

== 2026-11-08

**Maildeno Editor** 

=== The editor and renderer are now open source

**@maildeno/editor v0.4.15**

==== Added

**You can set a column's width from the Column panel.** Select a column and open the Column tab: the new **Width** section has a slider and a number box, a strip that shows every column's share of the row, and an **Equalize** button. When a row has several columns, the others share what is left in proportion to their widths, so the row always adds up to 100%. A single column always fills the row. The Column 1, Column 2 and Column 3 tabs show each width under their name, and a nested row's columns work the same way.
++++
<br/>
++++
Widths are whole percentages, and a column can be as narrow as 5% and as wide as the others leave it (90% in a row of three). Typing a number outside that range is corrected when you leave the box. One drag of the slider is one undo step. A row with decimal widths (from Custom widths in the Layout tab) is rounded to whole percentages the first time you change one of its columns. Width is a desktop setting, so the Mobile tab shows a note instead of controls: a row that stacks shows its columns at full width on mobile.
++++
<br/>
++++
A row whose columns do not add up to 100%, such as one from an older template, shows a note with a **Fix to 100%** button, because the canvas and the exported email lay such a row out differently. Changing any of its columns repairs it too.

Inside the editor, `useEmailBuilder()` has a new `setColumnWidths(rowId, widths, debounced?)`. It takes one width per column, repairs them to whole percentages that add up to 100, and returns whether the row changed. The rules are in `core/columnWidths.ts`.

==== Fixed

**The Merge Tag and Link Tag tabs no longer clear when you switch to another tab.** The tag names and preview values you had typed, the Preview switch and which sections were open or collapsed were lost as soon as you opened another tab: Merge Tag to Link Tag, Tags to Styles, or General to Content. Preview could also be left on with nothing to turn it off. After you came back, the switch said "Preview OFF" and was disabled, while the canvas was still showing the preview values.
++++
<br/>
++++
They now stay for as long as the editor is open. The sidebar also remembers which tab you were on at each level, so coming back to General opens Tags where you left it. The values are sample data for previewing, so they are not saved in the template and are gone when the page is reloaded. Two editors on one page do not share them.
++++
<br/>
++++
The cause was that each tab is removed from the page while another one is open, and the two tag tabs kept their data in the component, so it went with it. The data now lives in the editor instance, next to the other preview state (`sidebarUi`, on what `useEmailBuilder()` returns), and a tab opened while the preview is on starts with the switch on.

== 2026-11-02

**Maildeno Editor**

=== Selects follow the selected block's value

**@maildeno/editor v0.4.14**

==== Fixed

**Selects no longer show the previous value when you open them.** After you picked a value in a select and then selected another block, opening Font Family, Weight, Heading Level or any other select showed the earlier value in the search box, cut the list down to that one option and put the check mark on it. Typing a new search appended to the stale text, so another option could not be found without clearing the box first. The closed label was always right, and values were always written to the right block; only what the open select showed was wrong.
++++
<br/>
++++
The shared `Select` now follows the selected block: the box starts empty, the full list shows, the check mark sits on the block's current value, and typing filters as before. This covers every select that uses it, in both the Vue component and the `init()` custom element.
++++
<br/>
++++
The cause was two copies of the selection that never followed the parent. `Select` never gave Reka's `ComboboxRoot` the current value, so Reka kept its own copy of the last item picked in that instance. It also reused the text Reka writes into the search box as the list filter, and that text was a snapshot of the label from the last reset. `ComboboxRoot` is now controlled by `modelValue`, and the search box is bound one way, so only what the user types reaches the filter. In the custom-element build the first click makes Reka close the list and `Select` reopen it, which is why ignoring Reka's writes only while the list is closed was not enough.

== 2026-11-01

**Opensource Renderer v0.3.1** · **JavaScript/TypeScript v2.2.0** · **Python v2.1.0** · **PHP v1.1.0**

=== Rendering engine updated (Opensource Renderer, JavaScript/TypeScript, Python, PHP)

==== Added

* **Mobile property overrides for Row, Column, and Row Spacer components.** Added support for rendering the editor's sparse `mobile` configuration in HTML, MJML, and React Email, ensuring mobile-specific styles are applied instead of falling back to desktop values.
** **Row:** `backgroundColor`, `backgroundGradient`, `padding`, `border`, `minHeight`, `gap`.
** **Column:** `backgroundColor`, `backgroundGradient`, `padding`, `border`, `verticalAlign`.
** **Row Spacer:** `height`, `backgroundColor`, `backgroundGradient`.
** Nodes with at least one non-null mobile property receive the required hook classes (`eb-<id>`, `eb-<id>-box`, `eb-<id>-outer`, `eb-<rowId>-gap`) for targeting mobile overrides.
** Mobile override rules are generated inside the `/* Mobile property overrides */` block, before component rules, preserving the order in which properties are written by the editor.
** Nodes without mobile overrides, or with IDs containing characters outside letters, digits, hyphens, and underscores, do not receive mobile hook classes or override rules.
** **HTML:** Rows with mobile border overrides now receive an outer wrapper even when the desktop border has no radius, ensuring the mobile border has an element to target.
** Hidden rows, columns, and row spacers, as well as row spacers with a height of `0`, are excluded from mobile override generation.

== 2026-10-30

**Maildeno Editor**

=== Mobile overrides for rows, columns, and row spacers

**@maildeno/editor v0.4.13**

==== Added

* **Per-device overrides for rows, columns, and row spacers**, as components already have. `NestedRow`, `Column`, and `RowSpacer` accept a sparse `mobile` object. These nodes have no `props`, so it sits on the node itself, while components keep theirs in `props.mobile`.
** **Row:** background, padding, border, `minHeight`, and `gap`.
** **Column:** background, padding, border, and `verticalAlign`.
** **Row Spacer:** `height` and background.
** A `padding` or `border` override replaces the whole object, so it must include every side or field, as it does for components.
** The shapes are exported as `RowMobile`, `ColumnMobile`, and `RowSpacerMobile`.
* **Backward-compatible storage.** Saving drops unset keys and an empty `mobile`; loading restores the null baseline. `schema_version` stays `"1.0"`, and a template without `mobile` loads and saves exactly as before. A template with these `mobile` objects can still go through 0.4.12: its load and save code keeps them and its exporters ignore them.
* **Exporter support.** The HTML, React Email, and MJML exporters write the mobile rules and add an `eb-` class only to elements that have overrides, so a template without overrides exports as before, apart from the entries under Changed and Fixed. All three exporters now build a row's markup with one shared module, `export/shared/nodeBox.ts`. For HTML this changes nothing; React Email and MJML are covered below.
* **Canvas and Preview.** The editor canvas and the Preview screen draw these overrides on mobile, the same way they draw component overrides, so what you see matches the exported email. A row's mobile `gap` only applies while the row is stacked on mobile and has a gap on desktop, because that is when the exported email has gap cells to resize.
* **Desktop and Mobile tabs in the Row, Column, and Row Spacer panels**, matching the component panels. In Mobile mode each overridable control shows a badge and a Reset button, and an untouched control shows the desktop value. The name and the background image stay on Desktop. A row's mobile **Gap** appears only while the row is stacked and has a gap on desktop, with a note when it does not. A mobile border that ends up equal to the desktop border is dropped, so the exported markup does not change for no visible reason.
* The README and the framework guides show a row, a column, and a row spacer with a sparse `mobile` object under "Getting content out", and list what each can override.

==== Changed

* **React Email export:** the wrapper `<div>` of a row with a simple border (border width above 0, no radius) now writes `border` before `lineHeight` and `fontSize`. The rendered result is the same, and exports of every other row are unchanged.
* **MJML export:** a nested row is now built the same way as a top-level row and as in the HTML export: a `<td>` that carries the background, the corner radius, and the clip, around a `<div>` that carries the padding. The corner radius on that `<td>` is the row's radius plus 2px, as in the HTML export. A row with a border and a radius now gets an outer `<div>` (border, radius, clip) around an inner `<div>` (padding), where it used to get a single `<div>`.
* **MJML export:** the row `<td>` and the `<div>` inside it write some style declarations in a different order, for example `line-height` before `font-size`. The rendered result is the same.

==== Fixed

* A `mobile` background override that switches a component to a solid colour over a desktop gradient is no longer dropped when the template is saved and loaded again. The solid colour still applied in exported email, but the editor and Preview fell back to the desktop gradient on mobile.
* **MJML export:** a top-level row with a border and no radius wrote its border and padding on the `<td>` and again on the `<div>` inside it, so the border was drawn twice and the padding applied twice. They are now written once, on the `<div>`, as in the HTML export.
* **MJML export:** a nested column wrote its border on its `<td>` and again on a wrapper `<div>` around its content. They are now written once, on the `<td>`, and the wrapper `<div>` is gone.
* **MJML export:** a nested row with a border lost its background and ignored its corner radius, because the radius was written as a bare number inside the `border` rule and broke the declaration after it. Both now apply.
* Number sliders no longer write a value when you click into the number box and out again without typing. In Mobile mode that created an override equal to the desktop value, with its badge and Reset button. On Desktop nothing showed, but it still added an undo step that changed nothing and fired `onChange`. Text that is not a number, such as `abc` or an empty box, is now replaced by the current value when the box loses focus. A value outside the slider's range is still brought back into it.

==== Removed

* `wrapWithContainerDiv` and `wrapWithContainerDivReact` (`export/shared/containers.ts`), the old row wrappers. The three exporters build rows with the shared row box now, and nothing else used them. They were internal and not part of the public API.

== 2026-07-10

**JavaScript/TypeScript v2.1.3** · **Python v2.0.3** · **PHP v1.0.0**

=== Rendering engine updated (JavaScript/TypeScript, Python)

==== Changed

**Updated the embedded WebAssembly rendering engine.** The SDK now ships with the latest `engine.wasm`, incorporating rendering improvements and internal engine refinements while maintaining API compatibility.

==== Internal

**Aligned the SDK with the unified Maildeno rendering engine build system.** The rendering engine is now produced from the same cross-platform build pipeline used across Maildeno SDKs, ensuring consistent rendering behaviour between WebAssembly and native runtimes.

=== PHP: Wasm/FFI engine replaced with a native binary — breaking

==== Changed — breaking

**Rendering moved off wasm/FFI entirely.** Previous builds rendered through an embedded `engine.wasm` via PHP FFI bindings to wasmtime (`ext-ffi` + a ~15–25MB wasmtime shared library per platform). That path — `MaildenoEngine`, `engine.wasm`, the `wasmPath`/`libPath` config keys, and the `lib/` directory — is removed. `NativeEngine` is now the only engine: no FFI extension, no wasmtime runtime to distribute, and a bundled binary typically well under 1MB per platform.

* `ext-ffi` is no longer referenced anywhere in `composer.json`.
* `symfony/process` is now a hard `require` (`^6.4 || ^7.0`), not a `suggest` — it's needed for every render, not an optional integration.

==== Added

* `NativeEngine` — the render engine. Runs a small platform-native `maildeno-engine` executable (via `symfony/process`), bundled with the package under `bin/<platform>/`. `MaildenoClient` resolves and uses it automatically — no configuration required for normal use.
* `RenderEngine` — the interface `NativeEngine` implements, so `MaildenoClient` (and its 3rd constructor argument, for injecting a pre-built or stub engine) isn't coupled to one concrete implementation.
* `MaildenoClient` accepts an optional `enginePath` config key with an exact binary path, for the rare case of overriding auto-detection (a non-standard binary location, or testing against a stub).

NOTE: This lands the same day as the JS/Python engine refresh above — both come out of the same unified cross-platform engine build pipeline described in that entry's Internal note. PHP simply goes one step further, dropping Wasm entirely in favor of a native binary.

See xref:sdk:php-rendering.adoc[PHP Rendering] and xref:sdk:php-caching.adoc[PHP Caching] for current behavior.

== 2026-07-06

**PHP v1.0.0**

Initial stable release of the PHP SDK, with full feature parity with the JavaScript/TypeScript SDK (v2.1.2).

=== Added

* `MaildenoClient` — fetches template JSON from the Maildeno API, caches it, and renders via the embedded Wasm engine. Public surface mirrors the JS SDK: `render()`, `renderHtml()`, `renderReact()`, `renderMjml()`, `listCached()`, `deleteCached()`, `clearCache()`, and the deprecated `invalidate()` alias.
* Caching — `MemoryStore` (in-process, TTL, oldest-entry eviction) and `DiskStore` (one atomic JSON file per template, survives restarts) behind a `TemplateCache` facade. Defaults: 5-minute TTL, 50 entries.
* Stale-on-error fallback — when the TTL has expired and the API is unreachable, the last known-good template is used and `RenderResult::$fromStaleCache` is set to `true`.
* `MaildenoError` — single error type with a string `code`, HTTP `status`, and optional validation `issues`. Status mapping matches the JS SDK (401/403/404/422 → codes; network → `NETWORK_ERROR`; timeout → `TIMEOUT`).
* `Minify` — whitespace compaction for `html`, `mjml`, and `react-email`, a faithful port of `minify.ts` with shared golden test vectors.
* `MaildenoEngine` — FFI-to-wasmtime bridge running the same `engine.wasm` as the other SDKs; rendered output is byte-for-byte identical.
* Injectable HTTP transport (`HttpTransport`, default `CurlTransport`) and optional engine injection, for custom clients and testing.
* Zero-dependency autoloader and a 97-test framework-free suite.

NOTE: The `MaildenoEngine` Wasm/FFI bridge shipped here was replaced four days later — see PHP v2.0.0 above.

== 2026-06-12

**JavaScript/TypeScript v2.1.1** · **Python v2.0.1**

=== Fixed

* Visibility context now handles non-string values. Context passed as a number or boolean (e.g. `context: { premium: true }` in JS, `context={"premium": True}` in Python) was read as empty, so visibility rules comparing against it never matched and the affected rows were always hidden. Numbers and booleans are now coerced for comparison — `2` matches `"2"`, and `true`/`True` matches `"true"`. String context was unaffected.
* Visibility context keys are now matched case-insensitively. Capitalized or camelCase keys (e.g. `Premium`, `orderCount`) previously failed to resolve. The rule `tag` must still match the context key _name_ — `isPremium` and `premium` remain distinct.

== 2026-06-07

**JavaScript/TypeScript v2.1.0** · **Python v2.0.0**

=== JavaScript/TypeScript v2.1.0

==== Added

* Disk cache strategy — set `cache: { type: "disk", path: "..." }` to persist template JSON to the local filesystem. Disk-cached entries survive process restarts and are shared across workers on the same filesystem.
* Unified `cache` config object — `type`, `path`, `ttl`, and `maxEntries` now live under a single `cache` key.
* `client.listCached()` — returns the IDs of all templates currently in the cache.
* `client.deleteCached(templateId)` — removes a single template from the cache. Replaces `invalidate()`.
* `CacheConfig` type exported from the package root.

==== Changed

* `client.clearCache()` is now async (was sync). Awaiting it is required in disk mode; memory mode resolves immediately, so existing code that does not `await` still works in practice.
* `client.invalidate(templateId)` is now async and deprecated — it delegates to `deleteCached()` internally, so existing code keeps working.

==== Removed — breaking

* `cacheTtl` top-level config option — moved into `cache.ttl`.
* `cacheMaxEntries` top-level config option — moved into `cache.maxEntries`.

See xref:sdk:js-caching.adoc[JS Caching] for the full caching reference.

=== Python v2.0.0

==== Changed — breaking

* Rendering is now local. The SDK fetches template JSON once via `GET /v1/sdk/template/{id}` and renders in-process using the embedded Wasm engine. Your merge tags {amp} visibility context never leave your server.
* `POST /v1/sdk/render` is no longer called. Existing direct-HTTP integrations keep working until the endpoint is removed (see the `Deprecation` response header).
* `RenderResult` gains an optional `from_stale_cache: bool = False` field. Code that reads `.output`, `.target`, or `.template_id` is unaffected.
* `invalidate(template_id)` is deprecated — use `delete_cached(template_id)`.

==== Added

* `wasmtime` runtime dependency — the Wasm engine that runs the embedded renderer (Linux, macOS, and Windows on Python 3.9+).
* `engine.wasm` shipped inside the `maildeno` package, located via `importlib.resources` (works in wheels, editable installs, virtualenvs, Lambda layers, and Docker).
* In-process template cache — template JSON is cached after the first fetch; subsequent renders to the same `template_id` have zero network overhead.
* Stale-on-error fallback — if the TTL expires and the server is unreachable, the SDK renders from the last known-good cached copy and sets `result.from_stale_cache = True` rather than raising.
* `cache=` constructor parameter — memory (default) or disk.
* `list_cached()`, `delete_cached(template_id)`, and `clear_cache()` cache-management methods.
* `CacheConfig` and `TemplateJson` TypedDicts exported from the package root.
* Thread-safe Wasm singleton — loaded lazily on the first render and reused for the process lifetime, with a lock for exactly-once initialisation.
* Async Wasm via thread executor — `AsyncMaildenoClient` dispatches renders to asyncio's default thread-pool executor so the event loop is never blocked.

See xref:sdk:py-caching.adoc[Python Caching] for the full caching reference.
